# TikuAdapter 项目宪法 v1.0.0

## 核心原则

### I. 测试先行（不可协商）
功能代码先写失败测试，确认因功能缺失而失败，再写最小实现使其通过。修复类改动必须先有复现失败测试。

### II. 密钥与敏感数据不入职
API 密钥、口令、个人数据一律不入 git（含提交历史）。配置文件入库的只放占位符模板；运行配置含真值时必须被 .gitignore 覆盖。公开发布前全历史检索敏感字符串必须零命中。

### III. 独立复核
实现者不复核自己的改动。审查发现必须带可执行复现命令（问题在时非零、修好后归零），复核通过才算关闭。

### IV. 单源真值
同一事实只有一个权威来源：运行配置以 config.yaml 为准、题库数据以 SQLite 为准、用户以 users 表为准。任何副本必须注明派生自何处、如何再生成。

### V. 发布可重复
版本发布由标签触发的自动化流水线完成，任何人从同一标签都能构建出等价产物。发布物不含密钥、不含本地路径。

### VI. 简单优先
不为想象中的需求加抽象。能用现有机制解决的，不引入新依赖；每个新依赖都要有为什么现有机制不够的理由。

## 治理

违反上述原则的改动在审查中标记为 blocker；修正后需记录违反原因与防复发措施。
